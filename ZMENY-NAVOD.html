Návod na úpravy – Donut & Broker Chart

1. Donut chart – šířka prstence +4px

Soubor: src/app/components/co-donut-chart/co-donut-chart.component.ts
Řádek: ~244

Vlastnost computedDonutSize určuje velikost vnitřní díry donutu (v % z poloměru). Menší procento = širší prstenec. Při height 280px: poloměr ~140px, ring = 140 × (1 - 0.77) = 32.2px → pro +4px: 36.2px → size = 1 - 36.2/140 ≈ 74%.

Změnit

computedDonutSize = '77%';

Na

computedDonutSize = '74%';

Celková velikost (height) zůstává beze změny na 280px. Mění se jen poměr díry, čímž se prstenec rozšíří o ~4px.

2. Broker chart – hover puntík jen u jedné křivky

Soubor: src/app/components/co-value-performance-chart/co-value-performance-chart.component.scss
Řádek: ~163 (za existující pravidlo .apexcharts-marker { transition: none; })

Přidat za existující pravidlo

// Existující pravidlo (NEMĚNIT):
.apexcharts-marker {
  transition: none !important;
}

// NOVÉ – zobrazit hover marker jen u první křivky
.apexcharts-series-markers-wrap:not(:first-of-type) .apexcharts-marker {
  opacity: 0 !important;
  r: 0 !important;
}

Toto pravidlo patří dovnitř bloku :host ::ng-deep { ... }, který už v souboru existuje (řádek 121). Tooltip se stále zobrazí s hodnotami obou křivek, ale vizuální puntík na grafu bude jen u první (hlavní) křivky.

3. Column chart V2 – hover aktivuje jen danou skupinu, ne celý graf

Komponenta: libs/golem-ng/src/lib/co/chart-v2/column-chart/ (CoColumnChartV2Component)

Současné chování: při najetí myší na sloupec se ztmaví celý graf — všechny série ve všech skupinách dostanou opacity: 0.35, plná zůstane jen celá hoverovaná série. Dělá to CSS třída co-column-chart--hovering, která se přidává na root element při každém hoveru na datapoint.

Cílové chování: reaguje jen hoverovaná skupina — hoverovaný sloupec zůstane plný, ostatní sloupce téže skupiny se ztmaví na 0.35, všechny ostatní skupiny zůstanou nedotčené. Hover z legendy (zvýraznění celé série přes highlightApexSeries()) zůstává beze změny.

Úprava má 3 kroky: smazat CSS ztmavení (HTML + SCSS) a přidat JS zvýraznění skupiny (TS).

Krok 1 – HTML: smazat class binding

Soubor: column-chart.component.html
Řádek: ~1–4 (root element)

Smazat řádek s bindingem --hovering

<div
  class="co-column-chart"
  [class.co-column-chart--loading]="loading"
  [class.co-column-chart--hovering]="hoveredSeriesIndex() !== -1 && !isLegendHover()"
>

Signály hoveredSeriesIndex a isLegendHover v TS zůstávají — používá je legenda.

Krok 2 – SCSS: smazat celoplošné ztmavení

Soubor: column-chart.component.scss
Řádek: ~147–157

Smazat celý blok

// Hover state - dim non-hovered series (chart hover via CSS)
.co-column-chart--hovering {
  .co-column-chart__chart-container ::ng-deep {
    .apexcharts-series {
      opacity: 0.35;
    }
    .apexcharts-series:hover {
      opacity: 1;
    }
  }
}

Pozn.: pravidlo .apexcharts-series { transition: opacity ... } výše v souboru (ř. ~34) ponechat — plynulý přechod se hodí i pro nové chování. Kvůli plynulému přechodu na jednotlivých sloupcích přidej ještě transition na bar-area (pokud tam už není):

Přidat do bloku ::ng-deep (u ř. ~66 „Bar border radius")

.apexcharts-bar-area {
  transition: opacity 150ms ease;
}

Krok 3 – TS: přidat zvýraznění skupiny

Soubor: column-chart.component.ts

3a) V updateChartConfigs() → chartConfig.events → createAxisHoverHandlers (ř. ~250–262) doplnit volání highlightBars() do obou handlerů:

Upravit onEnter / onLeave

...createAxisHoverHandlers({
  onEnter: ({ seriesIndex, dataPointIndex }) => {
    this.hoveredSeriesIndex.set(seriesIndex);
    this.highlightBars(seriesIndex, dataPointIndex);
    const value = this.data.series[seriesIndex]?.data[dataPointIndex] ?? 0;
    const category = this.data.categories[dataPointIndex] ?? '';
    const seriesName = this.data.series[seriesIndex]?.name ?? '';
    this.columnHover.emit({ seriesIndex, dataPointIndex, value, category, seriesName });
  },
  onLeave: () => {
    this.hoveredSeriesIndex.set(-1);
    this.highlightBars(-1, -1);
    this.columnHover.emit(null);
  },
}),

3b) Přidat novou privátní metodu — např. hned za highlightSeries() (ř. ~443–446):

Přidat metodu highlightBars()

/**
 * Dimuje ostatní sloupce ve stejné skupině při hoveru.
 * Sloupce z jiných skupin zůstávají nedotčeny.
 */
private highlightBars(activeSeriesIndex: number, activeDataPoint: number): void {
  if (!this.isBrowser) return;
  const bars = (this.elementRef.nativeElement as HTMLElement)
    .querySelectorAll('.apexcharts-bar-area') as NodeListOf<SVGElement>;
  bars.forEach(bar => {
    if (activeDataPoint === -1) {
      bar.style.removeProperty('opacity');
    } else {
      const seriesIndex = Number.parseInt(bar.getAttribute('index') ?? '-1', 10);
      const dataPointIndex = Number.parseInt(bar.getAttribute('j') ?? '-1', 10);
      if (dataPointIndex === activeDataPoint) {
        // stejná skupina: hovered bar plný, ostatní bary skupiny ztmavit
        bar.style.opacity = seriesIndex === activeSeriesIndex ? '1' : '0.35';
      }
      // jiná skupina (dataPointIndex !== activeDataPoint): nedotýkat se
    }
  });
}

ApexCharts renderuje každý sloupec jako path.apexcharts-bar-area s atributy index (série) a j (datapoint = skupina) — stejné atributy, které už čte readApexBarAreaIndexes() v utils/chart-shared.ts. Metoda proto funguje i po applyColumnGap() (transform skupin na opacity nemá vliv).

Ověření

  1. Hover na sloupec ve skupině se 3 sériemi → plný zůstane jen hoverovaný sloupec, dva sousední ve skupině ztmavnou, ostatní skupiny beze změny.
  2. Odjetí myší → vše zpět na plnou opacity.
  3. Hover na položku legendy → dál ztmaví celé ostatní série napříč grafem (beze změny).
  4. Graf s 1 sérií → hover nesmí nic ztmavit (ve skupině je jediný sloupec).
  5. SSR build projde — metoda má guard isBrowser.

4. Column chart V2 – odsazení popisků os (Y: 4 px, X: 8 px + 4 px top padding)

Soubor: libs/golem-ng/src/lib/co/chart-v2/column-chart/column-chart.component.ts, metoda updateChartConfigs()

Cíl: popisky osy Y mají být 4 px od linie osy (pravý okraj textu → linie). Popisky osy X mají být 8 px pod osou + 4 px top padding labelu = celkem 12 px mezi osou a horním okrajem textu.

Důležité: u SVG <text> elementů padding nefunguje — jediná cesta je offsetX/offsetY v Apex konfiguraci (top padding se započítá do offsetu). Hodnoty offsetů jsou empirické: ApexCharts má u popisků X vestavěné odsazení a offsetY se do výsledné pozice promítá cca 2×. Proto po nasazení vždy přeměřit skriptem v kroku 3.

Krok 1 – Osa Y: offsetX

V this.yAxisConfig → labels změnit

labels: {
  show: this.showYAxisLabels,
  offsetX: 0,
  // -6 = výsledná mezera 4px mezi pravým okrajem textu a linií osy Y
  offsetX: -6,
  ...
},

Pozn.: default (offsetX: 0) dává jen ~2 px; posun je 1:1 (každý -1 offsetu = +1 px mezery).

Krok 2 – Osa X: offsetY

V this.xAxisConfig → labels změnit

labels: {
  offsetY: 4,
  // Výsledná mezera 12px mezi osou X a horním okrajem textu:
  // 8px odsazení od osy + 4px top padding labelu.
  // POZOR: offsetY se promítá ~2x, hodnota je empirická — ověřit krokem 3
  // (-3.25 = 8px, -1.25 = 12px)
  offsetY: -1.25,
  ...
},

Pozn.: s původním offsetY: 4 je mezera ~22 px. Posun se promítá ~2:1 (každý -1 offsetu = -2 px mezery). Nezvětšovat offsetY do plusu — popisky by se posunuly pod spodní hranu SVG a ořízly (SVG má overflow: hidden).

Krok 3 – Ověření měřením v DOM

Otevřít stránku s grafem, DevTools konzoli a spustit (měří všechny column charty na stránce; cíl: xGap ≈ 8, yGap ≈ 4):

Měřicí skript (DevTools konzole)

[...document.querySelectorAll('co-column-chart .apexcharts-canvas')].map((chart, ci) => {
  const horiz = [...chart.querySelectorAll('line')]
    .filter(l => l.getAttribute('y1') === l.getAttribute('y2'));
  const axisY = horiz.reduce((a, b) =>
    b.getBoundingClientRect().top > a.getBoundingClientRect().top ? b : a
  ).getBoundingClientRect().bottom;
  const xTop = Math.min(...[...chart.querySelectorAll('.apexcharts-xaxis-texts-g text')]
    .map(t => t.getBoundingClientRect().top));
  const yRight = Math.max(...[...chart.querySelectorAll('.apexcharts-yaxis-texts-g text')]
    .map(t => t.getBoundingClientRect().right));
  const plotLeft = Math.min(...[...chart.querySelectorAll('.apexcharts-gridlines-horizontal line')]
    .map(l => l.getBoundingClientRect().left));
  return { chart: ci,
    xGap: Math.round((xTop - axisY) * 10) / 10,
    yGap: Math.round((plotLeft - yRight) * 10) / 10 };
})

Pokud hodnoty nesedí (jiná verze ApexCharts, jiný font): doladit offsety podle naměřené odchylky — Y osa 1:1, X osa 2:1.

5. Column chart V2 – legenda odskakuje při načtení grafu (layout shift)

Komponenta: libs/golem-ng/src/lib/co/chart-v2/column-chart/

Projev: při hodně hodnotách se nejdřív vykreslí legenda, pak „odskočí" dolů a donačte se graf.

Příčina: legenda (co-chart-legend) je běžné Angular DOM a vykreslí se okamžitě. ApexCharts se ale mountuje asynchronně — do té doby má .co-column-chart__chart-container výšku ~0, takže legenda sedí hned pod nadpisem a po vykreslení grafu ji jeho výška (height + 15 px Apex parentHeightOffset) odstrčí dolů. Čím víc dat, tím déle render trvá a tím viditelnější skok je.

Oprava: rezervovat výšku containeru dopředu přes min-height. Aby rezervace seděla na pixel, vypne se Apex default parentHeightOffset (15 px) a nahradí se stejně velkým padding-bottom containeru — finální layout se nezmění.

Krok 1 – TS: vypnout parentHeightOffset

V updateChartConfigs() → this.chartConfig přidat

this.chartConfig = {
  type: 'bar',
  height: this.height,
  fontFamily: 'inherit',
  // Výšku rezervuje CSS min-height na containeru (viz šablona) — bez toho
  // se legenda vykreslí první a po async mountu grafu odskočí (layout shift).
  // Apex default 15px nahrazuje padding-bottom containeru.
  parentHeightOffset: 0,
  ...
};

Krok 2 – HTML: rezervovat min-height

V column-chart.component.html na chart-container přidat binding

<div class="co-column-chart__chart-container">
<div class="co-column-chart__chart-container" [style.minHeight.px]="height">

Krok 3 – SCSS: nahradit 15px offset paddingem

V column-chart.component.scss do .co-column-chart__chart-container přidat

.co-column-chart__chart-container {
  width: 100%;
  overflow: visible;
  // Náhrada za Apex parentHeightOffset (15px), který je vypnutý kvůli
  // rezervaci výšky přes min-height (prevence layout shiftu při mountu)
  padding-bottom: 15px;
  ...
}

Ověření

V DevTools konzoli — výška containeru musí být stejná s grafem i bez něj:

Ověřovací skript (DevTools konzole)

const el = document.querySelector('.co-column-chart__chart-container');
const canvas = el.querySelector('.apexcharts-canvas');
const withChart = el.getBoundingClientRect().height;
canvas.style.display = 'none';
const withoutChart = el.getBoundingClientRect().height;
canvas.style.display = '';
console.log({ withChart, withoutChart, ok: withChart === withoutChart });

Vizuálně: otevřít stránku s grafem s hodně hodnotami (případně DevTools → Performance → CPU throttling 6x) — legenda musí od prvního vykreslení sedět na finální pozici a graf se „donačíst" do rezervovaného místa nad ní.

⚠️ Slepá ulička – CSS transform NEPOUŽÍVAT

Nabízí se doladit pozici popisků X přes SCSS (.apexcharts-xaxis-texts-g { transform: translateY(4px); }) — nefunguje. Skupina popisků má vlastní SVG atribut transform="translate(0, ...)", do kterého ApexCharts promítá offsetY, a CSS transform tento atribut celý přepíše (nepřičte se) — popisky skočí na úplně jinou pozici. Ověřeno v demu. Vše řešit přes offsetY v TS konfiguraci.
